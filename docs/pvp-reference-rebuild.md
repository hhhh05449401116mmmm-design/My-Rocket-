# إعادة تصميم PvP — Crazy Rocket

## النتيجة والنطاق

أعيد بناء **واجهة PvP فقط** على أساس الفيديو المرجعي: دولاب داكن بشرائح منفصلة، ألوان مشاركين ثابتة، صور أو رموز داخل الشرائح، مؤشّر ثابت، ومركز يعرض العدّاد والحوض ورقم الجولة دون أن يدور. يظهر شريط المشاركين ثم زر أصفر/برتقالي، ثم قائمة Players، مع إبقاء التنقل السفلي الأصلي وهوية Crazy Rocket.

لم يُعد بناء المشروع، ولم يُعدّل `database.js` أو محرك اختيار الفائز أو معادلة الجائزة أو بقية الألعاب. تغييرات `server.js` محصورة بتوقيت PvP، مزامنة مرحلة LIVE، والتحقق من أهلية هدايا PvP؛ حقول المقتنيات الجديدة إضافية ولا تستبدل `value` المستخدمة في بقية الألعاب.

الحصة المنطقية لكل لاعب تساوي قيمة رهانه مقسومة على إجمالي الرهانات. التقسيمات الداخلية الصغيرة زخرفية ضمن حصة اللاعب وليست فرص فوز مستقلة. الشرائح الصغيرة تحتفظ بزاويتها الدقيقة؛ تُخفى تسميتها عند ضيق المساحة وتبقى معلوماتها في القائمة. التوقف البصري يستخدم الفائز الذي يرسله الخادم، ولا يختار العميل فائزاً.

## البيانات والمزامنة

الواجهة تستخدم `/api/pvp/state` و`/api/pvp-stream` و`/api/pvp/join` الموجودة. تستخدم `countdownEndsAt` و`serverTime` لعدٍّ تنازلي حقيقي مدته 20 ثانية، مع طلب حالة احتياطي كل 1.5 ثانية أثناء انقطاع SSE ومحاولة إعادة الاتصال كل 4 ثوانٍ. عند الخروج تتوقف الاتصالات والمؤقتات والتحريك. لا يوجد لاعبان أو حوض وهمي كبديل في واجهة الإنتاج؛ الجولة الفارغة تظهر بلا مشاركين.

يبقى زمن الدوران LIVE القائم في محرك المشروع دون إعادة تعريف؛ الـ20 ثانية هي العدّ التنازلي، ثم مرحلة الاختيار والنتيجة بحسب الحالات الموجودة.

أضاف API المقتنيات `pvpGiftUniqueId` و`pvpBetValue` و`pvpEligible` لعرض هوية الهدية الفعلية وقيمتها المعتمدة. لا تظهر الهدايا غير الموثّقة أو المقفلة أو المحجوزة أو مكافآت الصندوق غير المسكوكة كخيارات PvP. يحظر مسار join أيضاً الهدية غير الموثقة؛ ويظل قفل الهدية وتحديد قيمتها وتسويتها على الخادم.

## إصلاح عطل دورة الجولة الموجود

كشف اختبار الدورة الكاملة أن `launchPvpRound` يغيّر الحالة في الذاكرة إلى LIVE لكنه يترك قاعدة البيانات في COUNTDOWN. تسوية اللعبة الموجودة تشترط LIVE في قاعدة البيانات، فكانت ترفض التسوية وتبقى الجولة عالقة. أصبح الانتقال يكتب LIVE قبل عرضها. لم تُمس دالة اختيار الفائز أو توزيع الرصيد والهدايا.

التحقق البصري والوظيفي تم في Chromium بمحاكاة مقاسات الهواتف، وليس على جهاز iPhone فعلي داخل تطبيق Telegram؛ ينبغي مراجعة safe area على الجهاز الحقيقي قبل الإطلاق.

شُغّلت الملفات الخمسة عشر للاختبارات العامة بمهلة 25 ثانية مستقلة لكل ملف. نجحت 7 ملفات؛ 3 ملفات أظهرت إخفاقات، و5 ملفات انتهت بمهلة بسبب عدم اكتمالها. تمت المقارنة بمرجع `6859ac2` في نسخة أصلية منفصلة: تطابق رمز الإخفاق وأسماء الاختبارات الفاشلة في الحالات الثماني كلها. لذلك **لا ندعي أن كامل مجموعة الاختبارات ناجح**؛ الأعطال السابقة خارج نطاق هذا التعديل.

ملفات الإخفاق السابقة: `collectible-economics.test.js` و`collectibles.test.js` و`crash.test.js`. ملفات المهلة السابقة: `collectibles-stream.test.js` و`crash-cap.test.js` و`integration.test.js` و`telegram-webhook.test.js` و`test-balance.test.js`.

## إعادة تشغيل المعاينة

تستخدم المعاينة قاعدة SQLite مؤقتة وتوكن Telegram وهمياً محلياً وتمنع الشبكة الحقيقية إلى Telegram. تُنشأ حسابات معاينة داخل هذه القاعدة فقط، وتدير الجولة شيفرة PvP الحقيقية. لا تستخدم بيانات أو أرصدة أو مدفوعات حية.

```bash
npm install
node test-helpers/pvp-preview-server.cjs
# افتح http://127.0.0.1:3000
```

للفحص الاختياري بالمتصفح دون تعديل اعتماديات الإنتاج:

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node test-helpers/pvp-browser-check.cjs
# أو، مع Chromium مثبت:
CHROMIUM_PATH=/usr/bin/chromium node test-helpers/pvp-browser-check.cjs
```

يمكن ضبط `PVP_PREVIEW_URL` أو `PVP_BROWSER_OUTPUT` في أداة فحص المتصفح. أداة المعاينة ليست سيرفر إنتاج ولا ينبغي نشرها على عنوان اللعبة الحية.

## الدمج والإطلاق

العمل محفوظ محلياً في commit على الفرع `feat/pvp-reference-layout`. رفض GitHub رفع الفرع بخطأ 403، رغم أن فحص المستودع يعرض `ADMIN`؛ لذلك لم تصل التغييرات إلى GitHub ولم يُفتح طلب دمج بعد. يلزم منح اتصال GitHub المستخدم صلاحية كتابة محتويات هذا المستودع لاستكمال الرفع. صُدّر ملف patch للتعديل دون ملفات أسرار.

لا يتضمن العمل دمجاً في main أو نشراً حياً تلقائياً. راجع التسجيل والواجهة في المعاينة ثم اختبرها داخل Telegram قبل الدمج والنشر؛ خصوصاً الجولة المختلطة TON/Gift والصور الفعلية وهوامش الأجهزة.

## ملاحظات موجودة خارج النطاق

المستودع العام يتتبّع ملف `.env` يحتوي توكن البوت. لم نطبع قيمة أي سر أو ننسخها إلى مستندات أو اختبارات؛ يلزم تدوير السر وإزالته من تاريخ المستودع بخطوة أمنية مستقلة. كذلك المصادقة الحالية تعتمد معرّف المستخدم كتوكِن، واستعادة جولة نشطة بعد إعادة تشغيل السيرفر تحتاج مراجعة مستقلة قبل الإطلاق. هذه الأمور لم تُغيّر ضمن إعادة تصميم الواجهة.
