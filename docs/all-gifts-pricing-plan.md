# تعميم تسعير هدايا Crazy Rocket

## النطاق المطلوب
Plush Pepe كانت عينة فحص فقط وليست نطاق النظام. الكتالوج الفعلي المحضر يضم 15 صندوقًا و516 خانة هدية، تمثل 111 اسم هدية و306 مواصفات مختلفة. يشمل التنفيذ كل هذه المواصفات مع قابلية إضافة هدايا إلى الكتالوج دون كتابة حالات خاصة لأسماء الهدايا. هدايا المخزون التي لا توجد في الصناديق تمر بالمحرك العام نفسه.

## قواعد السعر
- هدّية بدون صفات محددة: أقل عرض TON لنوعها.
- نموذج محدد: أقل عرض TON لنوع الهدية والنموذج معًا.
- خلفية محددة: أقل عرض TON لنوع الهدية والخلفية معًا.
- النموذج والخلفية محددان: عرض يجمع الشروط معًا.
- Black وOnyx Black خلفيتان مستقلتان في كل هدية. لا دمج ألوان ولا تشابه أسماء ولا تحويل Stars إلى TON ولا سعر عام بديل لمواصفة محددة.

## التنفيذ
1. يبقى كتالوج Telegram مصدر هوية نوع الهدية. قائمة سمات إعادة البيع تستخدم الأسماء والمعرفات الرسمية.
2. إزالة قائمة الهدايا المرجعية الخاصة بـPlush Pepe. عند غياب سمة من البيانات أو عدم إرجاع الفلتر عروضًا، يُفحص سوق نوع الهدية نفسه دون فلتر، وتُفحص سمات عروضه مباشرة. هذا فحص مطابق للشروط وليس رجوعًا إلى السعر العام: يحسب السعر من العروض المطابقة فقط.
3. مشاركة فحص صفحات كل مجموعة بين مواصفاتها، مع مهلة وحد صفحات وتزامن محدود. البحث الناقص لا ينشر سعرًا. لا تجديد لعمر سعر قديم بمجرد قراءته من الذاكرة.
4. مرحلة التحقق تقرأ الكتالوج الكامل وتزيل تكرار المواصفات. تتقدم بدفعات صغيرة بدل إطلاق 306 طلبات في آن واحد، وتعرض تغطية الفحص وعدد الأسعار المتاحة وأسباب غياب البقية. لا معاملات مالية أو بيانات حسابات.
5. بعد نجاح المصدر على الكتالوج، تدمج النتيجة مع النسخة المالية المحلية المحضرة لتشمل العرض وقيمة الجائزة والبيع والرهان مع النسب الحالية. لا تفعيل مالي قبل موافقة إصدار محدد، لا إعادة كتابة أسعار معاملات الماضي، ولا اختلاق صفات لجوائز قديمة لم تحفظ صفاتها.

## بنية الملفات
- `telegramGiftPricing.js`: مطابقة وقراءة وأسعار ودقة ومهل لكل نوع هدية.
- `lootBoxGiftCatalog.json`: كتالوج الصناديق الحالي الموحد؛ مواصفات فقط لا مصدر أسعار.
- `giftPricingSourceProbe.js`: تقرير فحص كل مواصفات الكتالوج بدفعات محدودة.
- `test/`: اختبارات محرك المصدر والتغطية والطلبات والـHTTP بقواعد مؤقتة.
- النسخة المالية المحلية الأخرى تبقى مستقلة عن نشر مرحلة القراءة فقط.

## التصميم والبيانات
لا تغيير للصاروخ أو البيبي أو حركة الأزرار أو شاشة PvP. لا تعديل للرصيد أو البيع أو الرهان أو الرسوم أو فرص الجوائز خلال مرحلة التحقق. لا نشر على main أو Railway دون موافقة النسخة الجديدة المحددة.
