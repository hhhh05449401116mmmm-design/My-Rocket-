# PvP — فصل عجلة الرهانات عن شريط اختيار الفائز

المصدر هو Crazy Rocket الحالي في `index.html` و`server.js` و`database.js`. الفيديو الجديد `ScreenRecording_10-08-202611-52-26_1.mp4` هو المرجع الأحدث ويستبدل توقع توقف الدائرة العلوية على صورة الفائز.

## التنفيذ

الدائرة العلوية كاروسيل رهانات بخانات داكنة منفصلة ومتساوية، ثابتة السرعة عبر WAITING وCOUNTDOWN وLIVE وRESULT. الخانات الفارغة تعرض CRAZY / ROCKET نصًا فقط؛ رهان TON يظهر رمز TON وقيمته، ورهان Gift يظهر صورة الهدية وقيمتها. صور اللاعبين لا تظهر داخلها. تفاصيل اللاعبين وصورهم ونسبهم تبقى في شريط المشاركين والقائمة الحقيقية. الدائرة ديكور معلومات، ولا تمثّل فرص الفوز ولا تختار الفائز.

أثناء العدّ التنازلي يكون الشريط أفقيًا ثابتًا وقابلًا للتمرير بأسماء المشاركين الحاليين. عند دخول LIVE يتحول إلى مسار بطاقات حقيقية مكرّرة بصريًا وينسحب إلى اليسار تحت مؤشر وسط ثابت. توزيع التكرارات البصري يتناسب تقريبياً مع الرهانات؛ هو ليس آلية الفوز. بعد وصول RESULT يتباطأ إلى بطاقة الفائز الذي حدّده الخادم في منتصف الشريط. لا تُعرض النتيجة من توقع عميل أو اختيار عشوائي محلي. تكرار بطاقة موجودة ليس لاعبًا جديدًا؛ العدد والقائمة يظلان من بيانات الجولة وحدها.

نبقي عدّاد 20 ثانية والمنطق القائم للرهان الحقيقي TON/Gift وقفل الهدية وخصم الرصيد واختيار الفائز وتسويته. نضيف توقيت بدء حركة الشريط وحالة النتيجة إلى snapshot كي تعود الواجهة للحالة الصحيحة بعد إعادة الاتصال. نختبر على قواعد مؤقتة فقط؛ لا تُزرع حسابات تجريبية في قاعدة اللعبة أو شيفرة الإنتاج. هذا الطلب ليس تحديثًا لموقع Manus التجريبي، بل تعديل للمشروع الأصلي وتجهيزه لاختبار حسابات Telegram الفعلية.

## البنية والأصول

تبقى ملفات المشروع وبقية الألعاب كما هي. تعديل CSS وJS وmarkup محصور بكتلة PvP داخل `index.html`، وحقول وقت/استعادة الجولة في `server.js` إن لزم دون تغيير أسعار أو رصيد أو معادلة اختيار الفائز في `database.js`. تُحدَّث اختبارات `test/pvp-ui.test.js` و`test/pvp-api.test.js` وفحص المتصفح. الأصول الحالية TON/Gift/avatars تُعاد استخدامها؛ لا أصول أو أسماء لاعب مرجعي من فيديو Epic Gift.

## الإصدار

يجب حل صلاحية كتابة GitHub المرفوضة سابقًا 403 والتحقق من Project Token في Railway ومن خدمة اللعبة الصحيحة. لا نشر للغلاف `hosted-preview-server.cjs` أو `.env` أو قاعدة اختبار أو أرصدة وهمية على Railway. قبل push إلى main الذي يطلق autodeploy، يُعرض commit المصحح والخدمة والبيئة ونطاق التغيير في بطاقة موافقة إصدار حقيقي. رفض صلاحية الكتابة لا يُتجاوز بمسار بديل. بيانات وأرصدة وهدايا اللاعبين الحية تُحفظ ولا يعاد تهيئتها.
